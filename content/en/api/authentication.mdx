# Authentication

Every request needs an API key. A single Fenno key works with all three protocols — use the header
that matches the endpoint you call.

## Auth headers

<Tabs items={['OpenAI compatible', 'Anthropic native', 'Gemini native']}>
  <Tabs.Tab>
    `Authorization: Bearer`:

    ```http
    Authorization: Bearer $FENNO_API_KEY
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    `x-api-key`:

    ```http
    x-api-key: $FENNO_API_KEY
    anthropic-version: 2023-06-01
    ```

    <Callout type="info">
      The Anthropic SDK accepts either `api_key` or `auth_token`, but never send both in one request.
    </Callout>
  </Tabs.Tab>
  <Tabs.Tab>
    `x-goog-api-key` or the `key` query parameter:

    ```http
    x-goog-api-key: $FENNO_API_KEY
    ```
  </Tabs.Tab>
</Tabs>

## SDK setup

```python
from anthropic import Anthropic

client = Anthropic(
    base_url="https://api.fenno.ai",
    api_key="<FENNO_API_KEY>",
)
```

```ts
import { GoogleGenAI } from '@google/genai'

const ai = new GoogleGenAI({
  apiKey: process.env.FENNO_API_KEY,
  httpOptions: { baseUrl: 'https://api.fenno.ai' }
})
```

## Keys and permissions

- Create multiple keys per account to separate environments or business units.
- Keys inherit account-level model access and quota; permission changes apply immediately.
- If a key leaks, delete and recreate it — deletion is irreversible.

## Usage constraints

<Callout type="warning">
  Do not embed keys in browsers or mobile apps. For client-side access, proxy through your own
  backend or issue short-lived credentials.
</Callout>

## Usage and quota

Requests are metered by model and debited in real time. In the console you can inspect per-key
usage, remaining balance and limits, and rate-limit or failure records.

When quota is exhausted, requests return `402` or `429`; see [Errors & retries](/en/api/errors).
