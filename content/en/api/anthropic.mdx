# Anthropic native API

Base URL: `https://api.fenno.ai` (the SDK appends `/v1/messages`). Suitable for Claude Code, the
Anthropic SDK and any client that speaks the Messages API directly.

## Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/v1/messages` | Create a message |
| POST | `/v1/messages/count_tokens` | Estimate input tokens |
| GET | `/v1/models` | List models |
| GET | `/v1/models/{model}` | Retrieve a model |

## Authentication

```http
x-api-key: $FENNO_API_KEY
anthropic-version: 2023-06-01
content-type: application/json
```

## Basic call

```bash
curl https://api.fenno.ai/v1/messages \
  -H "x-api-key: $FENNO_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{
    "model": "claude-sonnet-4-5",
    "max_tokens": 512,
    "messages": [{"role": "user", "content": "Summarize this PR risk in one sentence"}]
  }'
```

```python
from anthropic import Anthropic

client = Anthropic(base_url="https://api.fenno.ai", api_key="<FENNO_API_KEY>")

msg = client.messages.create(
    model="claude-sonnet-4-5",
    max_tokens=512,
    messages=[{"role": "user", "content": "Summarize this PR risk in one sentence"}],
)
print(msg.content[0].text)
```

## Streaming

Event order matches Anthropic:

```text
message_start → content_block_start → content_block_delta*
→ content_block_stop → message_delta → message_stop
```

Branch on event types instead of assuming every delta carries text.

## Content blocks

`content` accepts a string or an array of blocks:

| Type | Purpose |
| --- | --- |
| `text` | Plain text |
| `image` | Image input (base64 or URL) |
| `document` | PDF and similar inputs |
| `tool_use` / `tool_result` | Tool calls and results |
| `thinking` | Reasoning content when supported |

<Callout type="info">
  Tool and thinking block shapes vary by model. When migrating between models, consume only the
  block types you need and keep a defensive fallback.
</Callout>

## Differences from OpenAI

- System prompt uses top-level `system`, not a system message.
- `max_tokens` is required.
- Tools use `input_schema`; results come back as `tool_result` blocks.
- Stop reason is `stop_reason` (`end_turn`, `max_tokens`, `tool_use`, …).
