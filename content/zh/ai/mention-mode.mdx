# @ 提及模式

在任意 Issue 或 PR 评论中，@ 提及 `@fennoai`，然后用自然语言描述你的需求。不需要特定语法 —— 直接描述症状或问题就好。

```text
@fennoai <用自然语言描述你的需求>
```

## 什么时候用提及模式

提及模式是纯对话模式 —— FennoAI 只返回文字回复：分析、解释、建议或开放性讨论。此模式不会编写代码或提 PR。

适用于：

- **有个 Bug，但不知道原因在哪** —— 描述症状，让 FennoAI 分析根本原因
- **想让 AI 解释某段代码** —— 粘贴代码片段或指向某个文件，问它是什么意思
- **想讨论某个方案的可行性** —— 在动手之前先聊聊设计决策的权衡

准备好采取行动时（写代码、Review PR、生成方案），切换到[命令模式 →](/zh/ai/commands)。

## 示例：分析 Bug

```text
@fennoai 我们升级 Redis 之后，登录接口对有效 token 返回了 401。
能帮我看看可能是哪里出了问题吗？
```

FennoAI 会查看最近的认证代码和 Redis 客户端配置变更，然后解释可能的原因。

## 示例：解释代码

```text
@fennoai 这个 `reconcileState` 函数是做什么的，
为什么它要循环三次？
```

## 示例：讨论设计决策

```text
@fennoai 我们在考虑通知服务用消息队列还是直接 HTTP 调用。
基于我们目前的架构，你有什么建议？
```

## 示例：问下一步怎么做

```text
@fennoai 这个 PR 有两个测试失败了，我应该怎么修，
同时不破坏其他已有行为？
```

## 提及模式 vs 命令模式

|          | 提及模式         | 命令模式（`/code`、`/review` 等） |
| -------- | ---------------- | --------------------------------- |
| **输入** | 自然语言         | 斜杠命令                          |
| **输出** | 纯文字回复       | 代码 PR、Review 评论、方案文档    |
| **适合** | 分析、讨论、探索 | 目标明确的具体操作                |
