# Claude Code 接入

Claude Code 通过 Anthropic Messages 协议连接 Fenno。本指南使用环境变量，不依赖第三方供应商切换工具，也不会修改你的本地配置文件。

## 1. 准备客户端与模型

按 [Claude Code 官方安装说明](https://code.claude.com/docs/en/setup)安装客户端，然后确认版本：

```bash
claude --version
```

准备 Fenno Key，并选择支持 Anthropic Messages、流式输出和工具调用的模型。先备份已有配置，不要同时使用多个工具修改供应商。

## 2. 配置当前终端

macOS / Linux / WSL 与 Windows PowerShell 分别使用以下配置：

```bash
export FENNO_API_KEY="<YOUR_FENNO_API_KEY>"
export ANTHROPIC_BASE_URL="https://api.fenno.ai"
export ANTHROPIC_AUTH_TOKEN="$FENNO_API_KEY"
export ANTHROPIC_MODEL="<YOUR_MODEL_ID>"
```

```powershell
$env:FENNO_API_KEY = "<YOUR_FENNO_API_KEY>"
$env:ANTHROPIC_BASE_URL = "https://api.fenno.ai"
$env:ANTHROPIC_AUTH_TOKEN = $env:FENNO_API_KEY
$env:ANTHROPIC_MODEL = "<YOUR_MODEL_ID>"
```

替换 Key 和模型 ID。基础地址是域名，不带 `/v1` 或 `/messages`；客户端会追加 `/v1/messages`。

<Callout type="info">
  `ANTHROPIC_AUTH_TOKEN` 发送 Bearer 认证；`ANTHROPIC_API_KEY` 发送 `x-api-key`。按[鉴权说明](/zh/api/authentication)选择一种，不要同时设置冲突凭据。
</Callout>

## 3. 核对配置并验证

```bash
cd your-test-project
claude
```

1. 在会话里运行 `/status`，核对 API 地址和当前模型。
2. 发送“只回复 OK，不读取或修改文件”。
3. 到 Fenno 控制台核对时间、模型和用量。
4. 在临时测试项目中单独验证文件读取与工具调用。

不要让模型回答“你用了哪个 API”来验证路由，模型并不能可靠地知道实际请求地址。

## 持久化与配置冲突

当前终端的变量不会自动带到其他窗口。需要长期使用时，可以把非敏感配置加入 shell 配置，Key 由你选择的安全凭据方式提供。

Claude Code 的 `settings.json` 中 `env` 可以覆盖 shell 环境变量。如果修改后仍指向旧地址，检查用户、项目与本地设置里的同名字段，再启动新会话。不要公开打印完整环境变量来排查。

如果后台轻量任务请求了不可用模型，可以按官方模型配置文档设置 `ANTHROPIC_DEFAULT_HAIKU_MODEL`，使用账户可用的精确 ID；主模型成功不代表所有后台模型映射都已正确配置。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 一直要求认证或返回 401 | 检查实际生效的认证来源、旧 Key 与 settings 的覆盖 |
| 404 / 模型不存在 | 检查域名后没有重复 `/v1`，模型支持 Messages 协议 |
| 主会话正常，后台请求失败 | 检查默认模型映射与账户权限 |
| 文本成功，工具请求失败 | 缩小成单个工具用例，核对参数和工具结果消息 |
| 429 / 额度不足 | 先读错误正文与配额，不要反复重试长会话 |

参考 [Claude Code 官方网关接入](https://code.claude.com/docs/en/llm-gateway-connect)与[模型配置](https://code.claude.com/docs/en/model-config)。更多问题见[通用排错](/zh/api/integrations/others)。
