# 模型与能力

Fenno 以统一协议层收敛不同厂商的模型差异，你只需要关心“用哪个模型、要什么能力”，
不需要为每个厂商单独处理鉴权、错误码和流式格式。

<Callout type="info">
  具体可用的模型清单以控制台展示为准，并会随上游开放情况调整。本页只说明能力维度与
  调用方式，不维护静态模型列表。
</Callout>

## 能力矩阵

| 能力 | 说明 | 典型端点 |
| --- | --- | --- |
| 文本生成 | 对话、补全、长文写作、代码生成 | `/v1/chat/completions`、`/v1/responses`、`/v1/messages` |
| 多模态输入 | 图片、PDF 等作为输入内容 | 同上（消息内容改为数组结构） |
| 工具调用 | Function Calling / Tool Use，可并行或多轮 | 同上（`tools` 字段） |
| 结构化输出 | JSON Mode / JSON Schema 约束（仅 OpenAI 兼容请求） | `/v1/chat/completions`、`/v1/responses`（`response_format`） |
| 推理模式 | 长思考、逐步推理，按 token 计费 | 同上（模型或 `reasoning` 参数） |
| 提示缓存 | 复用长前缀，降低重复上下文成本 | 同上（自动或显式缓存标记） |
| 流式响应 | SSE 增量返回，首 token 更快 | 同上（`stream: true`） |
| 图像生成 | 文生图、图像编辑 | `/v1/images/generations`、`/v1/images/edits` |
| 向量化 | Embeddings | `/v1/embeddings` |

## 模型标识

模型使用字符串标识，常见写法有 `gpt-*`、`claude-*`、`gemini-*` 等。建议：

- 在代码里把模型名集中为常量或配置项，便于切换；
- 生产环境固定具体版本，避免“最新别名”带来的行为漂移；
- 灰度时按 Key 或业务维度分流，而不是在客户端做随机选择。

## 计费口径

- 输入、输出、缓存读写分别计费，价格以控制台展示为准。
- 图像按张计费，向量按输入 token 计费。
- 失败请求（未产生上游 token）不计费，具体以账单明细为准。
